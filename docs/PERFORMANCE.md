# 性能实现与本机测量

原项目已经使用 SQLite。本项目继续采用可嵌入 C++ 进程的 SQLite，并通过 WAL、多个独立连接、预编译语句缓存、租户与学科索引、FTS5 三元组索引和分页查询减少重复工作。目录与图谱查询只读取必要字段，历史版本和打印归档按所属账户及关联 ID 查询。以上设计不构成“数据库引擎比原项目更快”的证明。

本地特征向量增加了线程安全的 LRU 缓存，正文相同即可复用，正文修改会产生新键。缓存最多 8192 条，键最多 64 KiB，按键、向量和容器开销估算的内存预算为 32 MiB；超大正文直接计算而不缓存。这个预算不代表整个服务的 RSS 上限。分词与向量计算在互斥锁之外执行，避免阻塞其他缓存命中请求。

2026-10-02 在 Apple M2 Pro、16 GB 内存、macOS 26.6.2、Apple Clang 21.0.0、SQLite 3.53.4 上，以 C++20 `-O3 -DNDEBUG -pthread` 测试 1500 篇合成中文笔记，每篇正文约 1281 字节，使用内存 SQLite。冷查询只清空向量缓存，数据库页缓存已热；完整检索与关联候选各执行 5 次冷查询和 5 次热查询，取中位数。编码冷查询执行一次，热查询取 5 次中位数。

| 操作 | 向量缓存未命中 | 向量缓存已命中 | 本次耗时比 |
| --- | ---: | ---: | ---: |
| 对整个合成语料编码 | 34.02 ms | 0.30 ms | 113.18 倍 |
| 完整 RAG 模式检索 | 60.84 ms | 29.48 ms | 2.06 倍 |
| 笔记关联候选检索 | 51.31 ms | 17.47 ms | 2.94 倍 |

缓存前后检索结果通过逐项相等检查，测试中的缓存估算占用约 5.8 MB。单独的自动化测试还覆盖并发命中、内容变化、条目淘汰、内存预算淘汰和超大键旁路。

这些数字只比较同一新版实现的向量缓存冷、热状态，没有对原 Node 项目做对照，也没有测量磁盘 I/O 或并发 HTTP 压力，因此不能外推为全系统加速倍数。当前向量检索仍按租户及筛选条件遍历候选；缓存减少重复编码，不能把大语料检索变成次线性复杂度。本地特征哈希提供词面相似度，不等同于远程语义嵌入模型。

在项目根目录运行 `backend/tests/run_notes_print.sh` 可执行相关测试，运行 `backend/tests/run_embedding_benchmark.sh` 可输出基准 JSON。原始测量保存在 [benchmark-embedding-cache.json](benchmark-embedding-cache.json)，基准源码位于 [embedding_benchmark.cpp](../backend/tests/embedding_benchmark.cpp)。
